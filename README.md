# PortalProstoev

Портал учёта простоев по вине ИТ-компании для промышленного сектора: регистрация простоев,
классификация вины ИТ, конструктор объединённых простоев, расчёт потерь и SLA, дашборды и KPI,
управление инцидентами и RCA, отчётность для руководства и заказчика.

## Технологический стек
- **Frontend + Backend:** Next.js (App Router) + TypeScript (strict)
- **UI:** Tailwind CSS + shadcn/ui, графики — Recharts
- **App DB:** PostgreSQL + Prisma ORM
- **Источник простоев:** Oracle DB (второй уровень) — read-only через серверный адаптер
- **ITIL-тикеты:** OMNITRACKER (связь many-to-many с инцидентами портала)
- **Аутентификация:** ADFS (SAML 2.0 / OIDC), маппинг групп AD → роли RBAC
- **Тесты:** Vitest + Playwright
- **Инфра:** Docker + docker-compose

## Среды и развёртывание
| | Разработка (сейчас) | Прод (позже) |
|---|---|---|
| Хост | Домашний ПК на Windows + WSL2 (Ubuntu) | Oracle Linux-сервер в корпоративной доменной сети |
| Oracle DB | недоступна | доступна (read-only) |
| OMNITRACKER | недоступен | доступен через API |
| AD FS / домен | недоступен | доступен (вход сотрудников) |

**Ключевое требование:** проект разрабатывается и запускается локально в WSL **без доступа** к
корпоративным ресурсам (Oracle DB, OMNITRACKER, AD FS). Все внешние интеграции работают в
**mock-режиме**, включаемом через переменные окружения. При переносе на прод-сервер те же
адаптеры переключаются на реальные системы **без изменения доменной логики и UI**.

Флаги окружения (пример):
```
INTEGRATION_MODE=mock        # mock | live   (Oracle DB, OMNITRACKER)
AUTH_MODE=dev                # dev  | adfs   (вход: локальный dev-логин | ADFS)
DATABASE_URL=...             # локальный PostgreSQL
```

## Быстрый старт (разработка в WSL)
> Заполняется по мере реализации проекта.

1. Скопировать `.env.example` в `.env` и при необходимости выставить `INTEGRATION_MODE=mock`, `AUTH_MODE=dev`.
2. Установить зависимости и поднять локальный PostgreSQL (docker-compose).
3. Применить миграции Prisma и залить seed-данные (справочники категорий вины ИТ, ставки потерь, тестовые простои).
4. Запустить dev-сервер и войти через dev-логин.

## Принципы разработки
- Мок-режим обязателен: проект должен собираться и работать без доступа в домен.
- Секреты только в `.env` / `.env.example`, никогда в репозитории.
- Деньги и длительности считаются только на сервере.
- Импорт из Oracle идемпотентен (без дублей).
- Все изменения пишутся в `AuditLog`.
