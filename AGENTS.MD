# AGENTS.MD — правила работы агента в проекте PortalProstoev

Проект: портал учёта простоев по вине ИТ-компании для промышленного сектора.
Полное описание проекта — в `project.md`.

## Обязательные правила документации
- **README.md обновлять всегда** при изменении: инструкций по запуску, переменных окружения, состава модулей, порядка миграций, способа запуска тестов.
- **AGENTS.MD обновлять всегда** при изменении: правил работы агента, стека, соглашений о коде, структуры репозитория, процессов.
- Обновление `README.md` и `AGENTS.MD` — часть Definition of Done. Задача не завершена, пока документация не соответствует коду.
- Документацию коммитить вместе с кодом в одном изменении, а не отдельным «потом».

## Ключевые технические решения
- **Стек:** Next.js (App Router) + TypeScript (strict), PostgreSQL + Prisma, Tailwind + shadcn/ui.
- **Аутентификация:** ADFS (SAML 2.0 / OIDC), маппинг групп AD → роли RBAC.
- **Источник простоев:** Oracle DB (второй уровень), read-only через серверный адаптер.
- **ITIL-тикеты:** OMNITRACKER (связь many-to-many с инцидентами портала).

## Среды разработки и прода (важно)
- **Сейчас:** разработка идёт на домашнем Windows-ПК в WSL без доступа к домену, Oracle DB и OMNITRACKER. Код обязан собираться и работать без этих ресурсов.
- **Позже:** перенос на Oracle Linux-сервер в корпоративной доменной сети, где все системы доступны.
- **Правило:** любую внешнюю интеграцию реализовывать за адаптером с реализациями `mock` и `live`; режим — через `.env` (`INTEGRATION_MODE`, `AUTH_MODE`).
- Не добавлять жёстких зависимостей от корпоративных сервисов на старте приложения; при недоступности — работать в mock-режиме, не падать.
- Секреты и строки подключения к прод-системам в репозиторий не коммитить.

## Правила кода
- Секреты только в `.env` / `.env.example`, не в репозитории.
- Деньги и длительности считаются только на сервере.
- Импорт из Oracle идемпотентен (без дублей).
- Все изменения пишутся в `AuditLog`.
