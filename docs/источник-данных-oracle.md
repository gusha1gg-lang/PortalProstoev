# Источник данных: база по простоям (Oracle)

Описание того, что мы выяснили про внешний источник простоев. Нужно для Этапа 6 (интеграция),
когда появится доступ к Oracle. Данные собраны из скриншота внутреннего сайта и выгрузки Excel.

## Где живут данные
- Внутренний сайт «Количество простоев» (разделы: Отчётность, Ввод данных, Документы).
- Данные сайта берутся из **Oracle DB** (доступ пока не выдан).
- Наша часть данных — записи службы **ДИТ** (прежнее название компании — ОМК-ИТ).

## Фильтры на сайте
- Начало периода, Конец периода, Задать время
- **Служба** — ответственная служба (наша = ДИТ)
- **Цех** — список цехов («АО ВМЗ — КЦ», «АО ВМЗ — МКС-5000» и т.д.)

## Структура таблицы простоев (колонки)

| Колонка | Пример | Смысл |
|---|---|---|
| НАЧАЛО | 2026-10-10 15:01:25 | Начало простоя |
| КОНЕЦ | 2026-10-10 15:24:47 | Окончание |
| ДЛИТЕЛЬНОСТЬ | 0ч.23мин. | Текстовая длительность (считаем сами из начала/конца) |
| ПРИЧИНА | *(пусто)* | Категория причины (требует уточнения) |
| ПРИМЕЧАНИЕ | «Не работает система ДМАП» | Текст, что произошло |
| АГГРЕГАТ | «Участок гидропресса №2 — П9046-2» | Конкретный агрегат |
| УЧАСТОК | «Участок ремонта и гидроиспытаний 1020» | Участок |
| ФИО | «Кондрушин А.М.» | Кто зафиксировал |
| СЛУЖБА | ДИТ | Ответственная служба |
| ЦЕХ | ТЭСЦ-4 | Цех |

## Иерархия (важно)
Реальная структура: **Цех → Участок → Агрегат**.
В портале так же: Цех = Workshop, Участок = Section, Агрегат = Unit. Слова приведены к реальным.

## Ключевой вывод для SQL-запроса
Наши простои = строки, где **`СЛУЖБА = ДИТ`**. Запрос отбирает записи по службе ДИТ за период.
Только чтение (`SELECT`), ничего не меняем.

## Важное наблюдение: дубли и «конструктор»
Один и тот же сбой порождает много записей. Пример (10.10.2026, система ДМАП):
одна остановка в 15:05–15:20 записана дважды (Орлов, Аникин), в 15:09 — дважды, в 15:10 — дважды и т.д.
Это один инцидент, размноженный по агрегатам и людям.
**Вывод:** функция объединения простоев в один кейс (Этап 4) обязательна, иначе потери будут задвоены.

## Формат данных
- Даты/время: `2026-10-10 15:01:25`.
- Длительность: текст вида `0ч.23мин.` — считаем из НАЧАЛО/КОНЕЦ.
- Пример проблемного ПО: **система ДМАП** (прикладное ПО / АСУ).
