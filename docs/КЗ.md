## Краткое описание предлагаемого варианта реализации
*(зона согласования Ключевых бизнес-экспертов)*

Создать веб-приложение **«PortalProstoev»**. Стек: Python, Django, PostgreSQL, Linux (сервер
Oracle Linux). Развёртывание в корпоративной сети, дополнительный сервер не требуется.

- **Назначение:** учёт простоев производственного оборудования по вине ИТ-службы; расчёт потерь
  и SLA; дашборды; управление инцидентами; уведомления.
- **Масштаб (по выгрузке за период):** ≈ 340 сбоев и ≈ 130 ч простоя по вине ИТ в год по группе;
  объём данных — десятки килобайт, отдельный сервер не требуется.
- **Источник данных о простоях:** внешняя корпоративная БД с простоями,
  доступ **только на чтение** (SELECT). Портал фильтрует строки по признаку нашей ИТ-службы и приводит
  их к удобному для ИТ виду (объединение дублей, классификация, потери, SLA).
- **Объединение дублей:** один и тот же сбой, задвоенный в источнике по агрегатам и людям,
  собирается в один кейс; длительность считается объединением интервалов — без двойного счёта.
- **Расчёт потерь и SLA:** часы × ставка участка + тонны × маржа; доступность, MTTR/MTBF, штрафы
  по договорам SLA. Формулы едины для дашборда, отчётов и страницы SLA.
- **Взаимодействие с ITIL-тикетами:** система тикетов — связь инцидента портала с тикетом.
- **Вход пользователей:** корпоративный вход (SSO, доменная учётная запись); роли назначаются по группам AD.
- **Уведомления:** email (SMTP); правила и получатели настраиваются в портале; запуск по расписанию
  (cron) — предупреждение о приближении к лимиту SLA, эскалация при превышении, ежедневная сводка.
- **Режимы интеграций** (mock / live) переключаются в настройках без изменения кода; на время
  разработки используется mock-режим (без доступа к корпоративным системам).
