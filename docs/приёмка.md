# Приёмка на mock-версии (Этап 11)

Документ для демонстрации портала. Аудитория — **ИТ-служба** (заказчик), поэтому акцент
на данных, интеграциях и расчётах, а не на «красивых картинках».

Демонстрация проходит **локально, без доступа к корпоративным системам**: внешняя БД с простоями,
система тикетов и корпоративный вход (SSO) заменены заглушками (mock-режим). Это заложено в архитектуру: на проде те же места
включаются флагами без правки кода.

## Подготовка стенда (5 минут)

```bash
# 1. Локальная БД (если ещё не поднята)
docker compose up -d

# 2. Структура БД
./.venv/bin/python manage.py migrate

# 3. Демо-данные одной командой (справочники, простои, SLA, уведомления, пользователи)
./.venv/bin/python manage.py seed_demo

# 4. Запуск
./.venv/bin/python manage.py runserver
```

Открыть: http://127.0.0.1:8000/ — портал попросит войти.

**Пользователи для показа** (пароль у всех `DevPortal2026!`, только для разработки):

| Логин | Роль | Что показывает |
|---|---|---|
| `operator` | Оператор | Просмотр простоев (правка — в админке), но нет доступа к журналу уведомлений |
| `specialist` | Специалист по простоям | Объединение дублей, просмотр уведомлений |
| `it_manager` | Руководитель ИТ | Дашборды, эскалации |
| `management` | Руководство предприятия | Отчёты (read-only) |
| `admin` | Администратор (суперпользователь) | Всё + админка |

## Сценарий демонстрации (по шагам)

| № | Что показываем | Где | Ожидаемый результат |
|---|---|---|---|
| 1 | **Вход и роли** | `/accounts/login/` | Обычная страница входа (на проде здесь будет корпоративный вход). В шапке — имя и роли. |
| 2 | **Дашборд** | `/` | KPI за месяц: число инцидентов, часы простоя, потери ₽, доступность, доля вины ИТ. Графики по месяцам, причинам, цехам. |
| 3 | **Импорт из источника** | `manage.py import_saarc` | «Создано: N». Повторный запуск → «Пропущено: N» (без дублей — идемпотентность). Фильтр «только простои нашей ИТ-службы». |
| 3a | **Синхронизация и версии записей** | страница `/sync/` | Кнопки «Забрать сейчас» и «Закрыть период». Если источник поправил/снял запись — она **не удаляется**, получает метку («Исправлен/Скорректирован/Снят»), попадает в список **«На проверку»** и в журнал. Закрытые периоды не меняются. |
| 3b | **Классификация вины ИТ** | страница `/catalog/` | Категории (АРМ, Инфраструктура, ЦИС, КИС, «Не наша ИТ-служба») и их причины редактируются **прямо в портале**: добавить/переименовать/скрыть. Записи не удаляются — только скрываются (можно вернуть). |
| 3c | **Структура (цеха → участки → агрегаты)** | страница `/catalog/structure/` | Цеха, участки и агрегаты правятся в портале: добавить, переименовать, сменить критичность, скрыть/вернуть. Общецеховые агрегаты заводятся прямо на цехе. Удаления нет — только скрытие. |
| 3d | **Раздел «Простои»** | страница `/downtimes/` и карточка простоя | Список простоев с фильтрами (период, цех, категория, вина, статус, источник, «на проверку», поиск). Карточка простоя: детали, классификация, тикет(ы) и история изменений. Доступен любому вошедшему. |
| 4 | **Объединение дублей** | Админка → Простои → «Найти дубли», либо страница кандидатов | Один и тот же сбой, задвоенный в источнике, собирается в **один кейс**. Длительность — объединение интервалов, без двойного счёта. |
| 5 | **Потери и SLA** | `/sla/` | По каждому цеху: потери ₽, доступность, MTTR/MTBF, ориентировочный штраф по договору. |
| 6 | **SLA-отчёт заказчику** | `/reports/sla/` | Отдельная печатная страница (можно отправить заказчику). |
| 7 | **Выгрузка** | кнопки «Выгрузить Excel» и «Выгрузить CSV» | Файлы открываются в Excel (`.xlsx` и CSV с `;`). |
| 8 | **Уведомления и эскалации** | `manage.py check_escalations`, `manage.py send_digest` | Письма печатаются в консоль (заглушка почты), видны в журнале `/notifications/`. Защита от повторной отправки. |
| 9 | **Админка** | `/admin/` | Справочники (цеха → участки → агрегаты), ставки потерь, категории вины, договоры SLA, правила уведомлений. |

## Что физически нельзя показать на mock (покажем на проде)

| Система | Сейчас (mock) | На проде |
|---|---|---|
| Внешняя БД с простоями | имитация набора строк | реальное подключение read-only |
| Система тикетов | имитация ответов API | реальные ITIL-тикеты |
| Корпоративный вход (SSO) | обычная страница входа | вход по доменной учётке |
| Почта | печать письма в консоль | реальный SMTP |

## Форма сбора замечаний

Заполняется по ходу показа. Каждое замечание получает номер и важность, чтобы ничего не потерять.

| № | Замечание | Важность | Что делаем | Статус |
|---|---|---|---|---|
| 1 |  | Высокая / Средняя / Низкая |  | Открыто |
| 2 |  |  |  |  |
| 3 |  |  |  |  |

**Важность:**
- **Высокая** — без этого нельзя внедрять (блокирует Гейт B).
- **Средняя** — важно, но можно после внедрения.
- **Низкая** — улучшение «на будущее».

## После демонстрации

1. Все замечания из формы → в список доработок (с оценкой).
2. Оценка объёма и затрат уточняется по факту замечаний.
3. Оформляется рабочее КЗ — см. [`КЗ.md`](КЗ.md) (🅱️ **Гейт B**).
4. Только после утверждения КЗ — переход к Этапу 12 (внедрение и прод).
