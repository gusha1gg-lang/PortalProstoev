# Модуль: каркас проекта (Этап 1)

Этот документ объясняет, из чего состоит каркас Django и зачем нужен каждый файл.
Новичку достаточно прочитать раздел «Что где лежит» и «Как запустить».

## Что где лежит

```
manage.py                     точка входа: через него запускаются все команды
requirements.txt              список зависимостей Python
docker-compose.yml            локальный PostgreSQL в Docker
.env / .env.example           настройки и секреты (реальный .env не в git)
config/
  settings/base.py            общие настройки для всех сред
  settings/dev.py             настройки разработки (WSL)
  settings/prod.py            настройки прода (Oracle Linux, домен)
  urls.py                     какие адреса куда ведут
  wsgi.py / asgi.py           точки входа для сервера на проде
templates/
  base.html                   общий «каркас» страницы (шапка, тело)
apps/                         здесь будут наши модули (catalog, downtimes, ...)
```

## Зачем разделены base / dev / prod
- `base.py` — то, что одинаково везде.
- `dev.py` — то, что только для разработки: `DEBUG=True`, локальные адреса.
- `prod.py` — то, что только для прода: `DEBUG=False`, требования безопасности (HTTPS, secure-cookies), домены из `.env`.

Такое разделение — стандарт Django. Оно не даёт случайно вынести «режим разработки» на прод.

## Флаги режимов (важно для переносимости)
В `.env` есть два флага:
- `INTEGRATION_MODE=mock|live` — работа с БД с простоями и системой тикетов (mock = заглушки, live = боевые системы).
- `AUTH_MODE=dev|adfs` — вход (dev = локальный, adfs = корпоративный SSO).

Сейчас оба стоят в dev-значениях, потому что локально нет доступа в домен. На проде меняются на `live` и `adfs` без правки кода.

## Как запустить (разработка в WSL)

```bash
# 1. Настройки
cp .env.example .env

# 2. Зависимости (один раз)
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt

# 3. База данных
docker compose up -d          # поднять PostgreSQL (порт 5433)

# 4. Структура БД
./.venv/bin/python manage.py migrate

# 5. Создать администратора (один раз)
./.venv/bin/python manage.py createsuperuser

# 6. Запуск
./.venv/bin/python manage.py runserver
```

Открыть в браузере:
- главная — http://127.0.0.1:8000/
- админка — http://127.0.0.1:8000/admin/

## Почему PostgreSQL на порту 5433
На домашнем ПК порт 5432 уже занят другими проектами (sla_planner, zabbix).
Чтобы не мешать им, наша БД слушает 5433. Это указано в `docker-compose.yml` и `.env`.
