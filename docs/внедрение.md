# Внедрение на прод (Этап 12)

Этот документ объясняет простыми словами, **как перенести портал на боевой сервер** так,
чтобы ничего не программировать: только скопировать, вписать настройки в `.env` и запустить.

> Рассчитан на сервер **Oracle Linux** в корпоративной (доменной) сети.
> Если что-то делает администратор — этот документ можно передать ему целиком.

## Что должно получиться

```
Браузер сотрудника  ──HTTPS──►  nginx (порт 443)  ──http──►  gunicorn (127.0.0.1:8000)
                                     │
                                     └─ отдаёт статику (/static/)
Приложение  ──►  PostgreSQL (база портала)
            ──►  БД с простоями (источник, только чтение)   [INTEGRATION_MODE=live]
            ──►  корпоративный вход SSO                       [AUTH_MODE=adfs]
            ──►  SMTP (письма-уведомления)
```

Основные части: **nginx** (HTTPS и статика), **gunicorn** (сам портал), **PostgreSQL** (база портала).

## Что понадобится от ИТ-службы (до начала)

- [ ] Сервер Oracle Linux в доменной сети (или готовый предоставленный).
- [ ] Доменное имя портала, напр. `portal.company.local`.
- [ ] HTTPS-сертификат и ключ для этого имени.
- [ ] Реквизиты SSO (см. `question.md`, В25).
- [ ] Реквизиты SMTP (В22–В24) и доступ к БД с простоями (В17, В46).
- [ ] Установленные пакеты: Python 3.12, PostgreSQL, nginx.

## Шаг 1. Пакеты на сервере

```bash
sudo dnf install -y python3.12 python3.12-pip nginx postgresql-server postgresql
sudo postgresql-setup --initdb        # если PostgreSQL ещё не настроен на сервере
sudo systemctl enable --now postgresql nginx
```

## Шаг 2. Разместить код

```bash
sudo mkdir -p /opt/portalprostoev
sudo chown "$USER" /opt/portalprostoev
# вариант А: из репозитория
git clone https://github.com/gusha1gg-lang/PortalProstoev.git /opt/portalprostoev
# вариант Б: распаковать присланный архив в /opt/portalprostoev
```

## Шаг 3. Виртуальное окружение и зависимости

```bash
cd /opt/portalprostoev
python3.12 -m venv .venv
./.venv/bin/pip install --upgrade pip
# LIVE-набор: Django, PostgreSQL-драйвер, gunicorn, драйвер источника, вход SSO
./.venv/bin/pip install -r requirements-live.txt
```

## Шаг 4. База данных PostgreSQL

Создаём базу и пользователя (пароль придумать надёжный и записать):

```bash
sudo -u postgres psql <<'SQL'
CREATE DATABASE portalprostoev;
CREATE USER portal WITH PASSWORD 'ЗАМЕНИ_НА_СВОЙ_ПАРОЛЬ';
ALTER ROLE portal SET client_encoding TO 'utf8';
ALTER ROLE portal SET default_transaction_isolation TO 'read committed';
ALTER ROLE portal SET timezone TO 'Europe/Moscow';
GRANT ALL PRIVILEGES ON DATABASE portalprostoev TO portal;
SQL
```

## Шаг 5. Настройки `.env`

```bash
cd /opt/portalprostoev
cp .env.example .env
nano .env
```

Заполнить (это единственное «программирование» — просто значения):

| Переменная | Что вписать (прод) |
|---|---|
| `INTEGRATION_MODE` | `live` |
| `AUTH_MODE` | `adfs` |
| `DJANGO_SECRET_KEY` | длинная случайная строка (сгенерировать, напр. `./.venv/bin/python -c "import secrets;print(secrets.token_urlsafe(50))"`) |
| `DJANGO_DEBUG` | `False` |
| `DJANGO_ALLOWED_HOSTS` | домен портала, напр. `portal.company.local` |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | `https://portal.company.local` |
| `POSTGRES_*` | из шага 4 |
| `SAARC_*` | реквизиты БД с простоями (В17, В46) |
| `OMNITRACKER_*` | реквизиты системы тикетов (если используется) |
| `ADFS_*` | реквизиты SSO (В25) |
| `DJANGO_EMAIL_BACKEND` | `django.core.mail.backends.smtp.EmailBackend` |
| `EMAIL_*`, `DEFAULT_FROM_EMAIL` | реквизиты SMTP (В22–В24) |

> Файл `.env` **не коммитится** в репозиторий — секреты остаются только на сервере.

## Шаг 6. Структура БД и статика

```bash
cd /opt/portalprostoev
./.venv/bin/python manage.py migrate            # создать таблицы
./.venv/bin/python manage.py collectstatic --noinput   # собрать стили для nginx
./.venv/bin/python manage.py createsuperuser    # служебная учётка администратора
```

## Шаг 7. Служба портала (systemd)

```bash
sudo cp deploy/portalprostoev.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now portalprostoev
systemctl status portalprostoev
```

Проверка, что приложение отвечает локально:

```bash
curl -I http://127.0.0.1:8000/
```

## Шаг 8. nginx (HTTPS + статика)

Положить сертификат и ключ по путям из конфига, затем:

```bash
sudo cp deploy/nginx-portalprostoev.conf /etc/nginx/conf.d/
sudo nano /etc/nginx/conf.d/portalprostoev.conf   # заменить домен и пути сертификата
sudo nginx -t
sudo systemctl reload nginx
```

## Шаг 9. Проверка

```bash
cd /opt/portalprostoev
./.venv/bin/python manage.py check --deploy
```

Ожидаемые предупреждения: про `SECRET_KEY` исчезнет после того, как в `.env` задан длинный
случайный ключ (шаг 5). Предупреждение про `SECURE_HSTS_PRELOAD` для внутреннего портала можно
оставить как есть — публичный «preload-список» браузеров для внутреннего домена не используется.

Открыть в браузере `https://portal.company.local` — должен открыться портал и вход через SSO.
Первый вход лучше сделать служебной учёткой (`AUTH_MODE=dev` временно, см. `config/settings/prod.py`),
чтобы заполнить справочники, затем вернуть `AUTH_MODE=adfs`.

## Шаг 10. Резервное копирование

./deploy/backup-db.sh        # ручная проверка — появится .sql.gz

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Бесконечный редирект на HTTPS | nginx не передаёт `X-Forwarded-Proto` либо не задан `SECURE_PROXY_SSL_HEADER` (уже в `prod.py`) |
| `400 Bad Request`, `DisallowedHost` | домен не добавлен в `DJANGO_ALLOWED_HOSTS` |
| `403 CSRF verification failed` | домен не добавлен в `DJANGO_CSRF_TRUSTED_ORIGINS` |
| Стили не грузятся (страница «голая») | не выполнен `collectstatic` или путь в nginx `location /static/` неверный |
| 502 от nginx | служба `portalprostoev` не запущена — смотреть `journalctl -u portalprostoev` |
| Ошибка входа SSO | проверить реквизиты `ADFS_*` и адрес возврата `https://<домен>/oauth2/callback` |
| Письма не уходят | проверить `DJANGO_EMAIL_BACKEND=smtp` и реквизиты `EMAIL_*` |
