# Отладка и полировка на тесте (Этап 11.5)

Цель этапа: **довести портал до «идеала» на локальном стенде ДО переноса на прод.**
Прод, реквизиты и согласования — самый последний шаг, когда сайт уже отточен.

Документ рабочий: идём по экранам сверху вниз, отмечаем галочками, всё найденное пишем
в **журнал замечаний** внизу.

## Как поднять стенд

```bash
cd /opt/PortalProstoev
docker compose up -d
./.venv/bin/python manage.py migrate
./.venv/bin/python manage.py seed_demo      # один раз, наполняет демо-данными
./.venv/bin/python manage.py runserver
```
Открыть: http://127.0.0.1:8000/  Пароль у всех демо-пользователей — `DevPortal2026!`.

| Логин | Роль | Доступ |
|---|---|---|
| `admin` | Администратор | Всё + админка `/admin/` |
| `operator` | Оператор | Просмотр простоев; журнал уведомлений — закрыт |
| `specialist` | Специалист по простоям | Объединение дублей, уведомления |
| `it_manager` | Руководитель ИТ | Дашборды, эскалации |
| `management` | Руководство | Отчёты (просмотр) |

## Чек-лист по экранам

Отмечайте `[x]` то, что проверено и работает. Если что-то не так — не отмечайте и пишите в журнал.

### 1. Вход и роли
- [ ] Страница входа открывается, поля логин/пароль на месте.
- [ ] Неверный пароль → понятное сообщение об ошибке, вход не выполняется.
- [ ] Вход под каждым из 5 пользователей проходит.
- [ ] `operator` не попадает в журнал уведомлений (получает «Доступ закрыт»).
- [ ] `specialist` / `it_manager` / `admin` — журнал уведомлений доступен.
- [ ] У не-админа нет ссылки «Админка» в шапке.

### 2. Шапка сайта
- [ ] Показаны имя пользователя и его роли.
- [ ] Ссылки «Дашборд», «Потери и SLA», «SLA-отчёт», «Уведомления» ведут куда нужно.
- [ ] Кнопка «Выйти» действительно выходит и возвращает на страницу входа.

### 3. Дашборд `/`
- [ ] Видны KPI: число инцидентов, часы простоя, потери ₽, доступность, доля вины ИТ.
- [ ] Фильтр «период» (месяц) переключается и меняет цифры.
- [ ] Фильтр «предприятие» работает (и «все предприятия»).
- [ ] Графики по месяцам, причинам, предприятиям отрисованы.
- [ ] Если графики не загрузились — цифры всё равно видны в таблицах.
- [ ] Кнопка «Выгрузить CSV» скачивает файл.

### 4. Потери и SLA `/sla/`
- [ ] По каждому предприятию: потери ₽, доступность, MTTR/MTBF, ориентировочный штраф.
- [ ] Смена периода меняет расчёт.
- [ ] Цифры совпадают с дашбордом за тот же период.

### 5. SLA-отчёт заказчику `/reports/sla/`
- [ ] Фильтры «период» и «предприятие» работают.
- [ ] Кнопка «Печать / PDF» вызывает печать.
- [ ] Страница выглядит пригодной для отправки заказчику.

### 6. Выгрузка CSV
- [ ] Файл открывается в Excel без «кракозябр» (кодировка и разделитель `;`).
- [ ] Данные соответствуют выбранному периоду/предприятию.

### 7. Журнал уведомлений `/notifications/`
- [ ] Виден список отправленных уведомлений с датой и темой.
- [ ] Понятно, кому и по какому правилу ушло письмо.

### 8. Админка `/admin/`
- [ ] **Справочники:** предприятия → цеха → участки → агрегаты (иерархия видна и правится).
- [ ] **Ставки потерь** (₽/час) — правятся.
- [ ] **Категории вины ИТ** и подкатегории — правятся.
- [ ] **Простои:** фильтры, поиск, сортировка работают.
- [ ] **«Возможные дубли»** — список кандидатов открывается.
- [ ] **Объединение в кейс** — выбранные записи объединяются в один кейс.
- [ ] **Кейсы:** открываются, видна история изменений (аудит).
- [ ] **Договоры SLA** — правятся.
- [ ] **Правила уведомлений** и получатели — правятся.

### 9. Импорт из источника (команда)
- [ ] `./.venv/bin/python manage.py import_saarc` → «Создано: N».
- [ ] Повторный запуск → «Пропущено: N» (без дублей).

### 10. Уведомления (команды)
- [ ] `./.venv/bin/python manage.py check_escalations` → письма печатаются в консоль, видны в журнале.
- [ ] `./.venv/bin/python manage.py send_digest` → сводка формируется.
- [ ] Повторный запуск не дублирует уже отправленное.

## Как сообщать о находках

Проще всего прямо мне в чат: **где** (какая страница), что **нажал**, что **ожидал**, что **получил**
(можно скриншот). Я вношу в журнал и чиню.

## Правила этапа

- Прод не трогаем, реквизиты не запрашиваем — пока сайт не отточен.
- Демо-данные можно пересоздавать: `manage.py seed_demo` безопасен для повторного запуска.
- Каждую правку фиксируем в журнале, чтобы ничего не потерялось.
