# Модуль: справочники и роли (Этап 2)

Документ объясняет структуру данных простыми словами. Здесь только справочники —
производственная структура, категории вины ИТ и ставки потерь. Сами простои будут в модуле `downtimes`.

Названия уровней соответствуют реальным терминам предприятия:
**Предприятие → Цех → Участок → Агрегат** (из источника данных Oracle — см. `источник-данных-oracle.md`).

## Таблицы (модели)

### Производственная структура
```
Предприятие (Enterprise)          — завод / филиал группы ОМК
 └─ Цех (Workshop)                — название уникально в пределах предприятия
     └─ Участок (Section)         — название уникально в пределах цеха
         └─ Агрегат (Unit)        — название уникально в пределах участка
```

Опознаём записи **по названию** (в источнике кодов нет). Поле «Код» — необязательное,
если где-то понадобится короткий код.

| Таблица | Поля | Смысл |
|---|---|---|
| Предприятие | название, код (необяз.), активно | Верхний уровень (АО "ВМЗ", ВлФ "МК ОМК-ЭкоМеталл", …) |
| Цех | предприятие, название, код (необяз.), активен | Например, ТЭСЦ-4 |
| Участок | цех, название, код (необяз.), активен | Например, «Участок отделки труб 1020» |
| Агрегат | участок, название, код (необяз.), критичность, активен | Например, «Площадка №9 окончательной приемки — ОПТ №9». Критичность: особо важный / высокая / средняя / низкая |

### Вина ИТ
```
Категория вины ИТ (ItFaultCategory)
 └─ Подкатегория вины ИТ (ItFaultSubcategory)
```
Пример категории — «Сеть», подкатегория — «Обрыв канала».

### Ставки потерь (LossRate)
Привязаны к участку и **версионируются по датам** (`valid_from`, `valid_to`).
Для конкретного простоя берётся ставка, действовавшая на дату этого простоя.
Поля: потери за час (₽), маржа за тонну (₽), период действия, примечание.
Есть проверка на уровне БД: дата окончания не раньше даты начала.

## Роли
Роли — это группы Django (создаются миграцией `accounts.0001_create_roles`):

- Оператор
- Специалист по простоям
- Руководитель ИТ
- Руководство предприятия
- Администратор

Имена ролей лежат в `apps/accounts/roles.py`. Там же — заготовка маппинга групп AD → роли
(заполним на этапе 9, когда подключим ADFS).

## Как вести справочники
Через админку Django: http://127.0.0.1:8000/admin/ — раздел «Справочники».
Можно добавлять цеха (с участками прямо внутри формы), агрегаты, категории вины
(с подкатегориями внутри) и ставки. Программировать для этого не нужно.

## Данные справочников
```bash
./.venv/bin/python manage.py seed_catalog
```
Заполняет реальный список от заказчика: **8 предприятий, 35 цехов**, а также 7 категорий вины
(с подкатегориями) и 4 демо-ставки. Детально наполняется только ТЭСЦ-4 (4 участка, 5 агрегатов) —
по данным выгрузки Excel. Команда идемпотентна — повторный запуск дублей не создаёт.

Полный список предприятий и цехов — в `источник-данных-oracle.md`.
