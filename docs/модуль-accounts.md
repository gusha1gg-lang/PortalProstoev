# Модуль: вход, роли и ADFS (Этап 9)

Документ объясняет простыми словами, как сотрудники входят в портал и что они видят.

## Два режима входа (переключаются флагом)

| Режим | Флаг в `.env` | Как входят | Где используется |
|---|---|---|---|
| Разработка | `AUTH_MODE=dev` | Обычная страница входа: логин/пароль | Локально в WSL |
| Прод | `AUTH_MODE=adfs` | Корпоративная учётная запись через ADFS | Oracle Linux в доменной сети |

**Главное:** переключение режима — это только изменение флага. Код страниц, шаблоны и роли
остаются теми же. На проде `AUTH_MODE` по умолчанию `adfs` (см. `config/settings/prod.py`).

## Как устроено

- **Вход.** В dev — стандартная страница Django (`/accounts/login/`). В проде ADFS перехватывает
  вход: сотрудник вводит свою доменную учётную запись, отдельного пароля для портала нет.
- **Выход.** Кнопка «Выйти» в шапке (безопасный POST-запрос).
- **Роли.** Роль — это группа Django. Список ролей — в `apps/accounts/roles.py`:

  | Роль | Кому |
  |---|---|
  | Оператор | Вносит простои |
  | Специалист по простоям | Разбирает и объединяет простои |
  | Руководитель ИТ | Смотрит дашборды и эскалации |
  | Руководство предприятия | Смотрит отчёты |
  | Администратор | Полный доступ |

- **Роли из AD.** При входе через ADFS портал смотрит группы сотрудника в AD и выдаёт
  соответствующие роли портала. Соответствие «группа AD → роль портала» задаётся картой
  `AD_GROUP_TO_ROLE` в `apps/accounts/roles.py` (сейчас пустая — заполняется после согласования,
  вопрос В25).

## Кто что видит

- **Дашборды, отчёты, SLA** — любой вошедший сотрудник.
- **Журнал уведомлений** (`/notifications/`) — роли «Руководитель ИТ», «Специалист по простоям»,
  «Администратор». Остальным — страница «Доступ закрыт».
- **Админка** (`/admin/`) — служебные учётки (staff).

## Как проверить в разработке

```bash
python manage.py seed_users   # демо-пользователи: operator, specialist, it_manager, management
```

Пароль у всех демо-пользователей — `DevPortal2026!` (**только для разработки!**).
Плюс администратор, созданный командой `createsuperuser`.

## Устройство (папка `apps/accounts/`)

| Файл | Что делает |
|---|---|
| `roles.py` | Список ролей и карта «группа AD → роль» |
| `decorators.py` | `role_required` — проверка роли на странице |
| `adfs.py` | Назначение ролей по группам AD при входе |
| `apps.py` | Включает ADFS-обработчик только при `AUTH_MODE=adfs` |
| `urls.py` / `templates/accounts/login.html` | Страница входа и выход |
| `management/commands/seed_users.py` | Демо-пользователи по ролям |

Настройки ADFS вынесены в `config/settings/adfs.py` и подключаются функцией `apply_adfs()`
только при `AUTH_MODE=adfs`. Пакет `django-auth-adfs` нужен только на проде — он в
`requirements-live.txt`.

## Что нужно от коллег из ПИ-ПС (В25)

Чтобы включить ADFS на проде, нужны: сервер ADFS, идентификатор приложения (Client ID),
секрет, Relying Party ID, а также имена групп AD для ролей. Пока поступают эти данные,
портал полностью работает в режиме `dev`, а вход по ADFS включается одним флагом.
