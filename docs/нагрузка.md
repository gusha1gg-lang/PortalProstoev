# Нагрузка и производительность

Короткий ответ: **портал почти не нагружает корпоративные системы.** Он не вмешивается в работу
оборудования, не пишет в источник данных и не опрашивает его постоянно.

## На что портал вообще может влиять

| Что | Как используется | Нагрузка |
|---|---|---|
| **Источник Oracle** (данные о простоях) | только чтение (SELECT), по расписанию | разовая, короткая |
| **Сервер портала** (Python/Django + PostgreSQL) | своя база, небольшой объём | низкая |
| **Сеть** | обмен небольшими порциями данных | ничтожная |

## 1. Источник данных (Oracle)

- **Только чтение.** Портал никогда не пишет и не меняет данные источника — учётная запись read-only
  (SELECT).
- **Не постоянный опрос.** Импорт запускается по расписанию (например, ночью, один раз в сутки или
  реже), а не «крутится» непрерывно. Между запусками соединения с источником нет.
- **Читаем только новое.** За один запуск запрашиваются строки за последний период (инкрементально)
  и **только по службе «ДИТ»**. Это один запрос на небольшую пачку строк.
- **Повторный запуск ничего не делает** (идемпотентность): уже загруженные строки пропускаются.

## 2. Сервер портала

- Стек: Python (Django) + PostgreSQL, веб-страницы. **Отдельный мощный сервер не требуется** —
  помещается на существующую виртуальную машину Oracle Linux.
- Пользователей немного (ИТ/ДИТ и специалисты предприятий), одновременная работа — единицы человек.
- Дашборды и отчёты считаются по данным портала, с индексами — за доли секунды.

## 3. Объём данных (из реальной выгрузки)

Реальная выгрузка за период: **28 строк за 2 дня по одному цеху** (ТЭСЦ-4), включая задвоения
по людям. Даже с большим запасом:

| Оценка | Значение |
|---|---|
| Один цех | ≈ 5 000 строк в год |
| Вся группа (с запасом) | ≤ 100 000 строк в год |
| Объём в базе за 10 лет | ≈ 200 МБ |

Для современной СУБД это **ничтожный объём**. Нагрузка на само хранилище — минимальная.

> Это оценка «сверху»: реальные простои по вине ИТ — событие нечастое, а не поток данных.

## 4. Что портал НЕ делает (важно для ИБ и производства)

- Не пишет и не изменяет данные в Oracle (только SELECT).
- Не работает в реальном времени и не опрашивает источник непрерывно.
- Не подключается к производственному оборудованию и АСУ ТП.
- Не создаёт повторной нагрузки при повторном импорте (защита от дублей).

## 5. Как мы гарантируем, что не нагрузим источник

- Импорт — по **расписанию** (cron), в удобное окно вне пиков.
- Только **инкрементальный** запрос (новый период) и фильтр по службе «ДИТ».
- Учётная запись **read-only**, доступ выдаёт служба сопровождения Oracle.
- Ограничение выборки по датам, чтобы запрос не читал всю таблицу.

## 6. Что уточнить у ДБА / службы сопровождения (см. В17, В31)

1. Размер исходной таблицы или представления.
2. Есть ли индекс по дате и по службе (чтобы запрос был быстрым).
3. Удобное окно времени для запуска импорта.
4. Разрешение на создание учётной записи только для чтения.

**Вывод:** по нагрузке препятствий нет — портал безопасен для источника и лёгок для сервера.
